# Secure remote app access with modern security controls (MFA/Device Trust)

**Implementation Effort:** Low 

**User Impact:** High 

## Overview
Secure access to remote applications by validating both user identity and device trust. Access should be granted only when users successfully authenticate with strong authentication methods and their devices meet organizational security, compliance, and risk requirements. Leverage Conditional Access, Intune compliance policies, Defender for Endpoint risk signals, and Global Secure Access to enforce Zero Trust access controls.

Device Trust ensures that access decisions consider the security posture of the device in addition to the user's identity. A successfully authenticated user should not automatically receive access if the device is unmanaged, non-compliant, or presents elevated risk. Device trust extends Zero Trust principles by continuously evaluating device health, compliance, and risk signals before granting application access.
## Understanding Device Trust

Device Trust is a core Zero Trust signal used to determine whether a device is sufficiently secure to access organizational resources.

Microsoft evaluates device trust using multiple signals, including:

- Device management status (Intune managed)
- Device compliance status
- Device risk level from Microsoft Defender for Endpoint
- Device identity in Microsoft Entra ID
- Operating system and security configuration state

Organizations should use Conditional Access policies to ensure that access is granted only from trusted devices that meet organizational security requirements.

Common examples include:

- Require devices to be marked as compliant
- Block access from high-risk devices
- Require approved application protection policies for mobile scenarios
- Restrict access to unmanaged devices
